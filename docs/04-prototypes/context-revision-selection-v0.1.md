# 同主题修订与输入选择约定 v0.1

日期：2026-09-30。对应 W1-03 / B06。2026-10-26 增补离线实现。2026-10-27 补充合并前边界。状态：**检查层已实现，32 项针对性及全套 124 项测试通过，尚未执行新的回答对照**。本文件补充[协作情境约定](collaboration-context-v0.1.md)，不修改现有来源适配接口。

本轮同条件回放发现：真实引用可以支持“曾经这样选择”，却不一定支持“现在仍偏好这样”。候选材料中存在较新的调整，但原标注未覆盖该主题，补位检索只选了较早消息。已有永久替代规则并未收到这些关系，因此不能将问题归为该规则失效。

## 1. 按字段解释变更

同一条自然语言消息可能同时涉及时段、报告频率、篇幅及工作流程。不能用“最后一条消息获胜”整体覆盖，也不能因旧消息部分仍有用就把整条视为当前约束。

| 表达的作用 | 期望 | 不允许的推断 |
| --- | --- | --- |
| 要求重新选择合适时段，没有指定新时刻 | 新选择依据是当前明确请求；旧具体安排待复核 | 已明确取消旧安排、已确认新时刻、旧时刻是长期固定偏好 |
| 增加每日进度简报与篇幅要求 | 频率、篇幅分别成为当前请求 | 自动取消每周规划/复盘，或要求每天额外工作 |
| 明确把某一字段改为新值 | 同范围、同字段取代，保留旧来源 | 把其他字段和其他范围一起删除 |
| 助手提出建议，或另一项目/任务发生变更 | 保持来源级别及范围边界 | 自动覆盖当前范围的明确用户表达 |

“没有取消证据”只意味着不能推断取消。它不证明旧流程已配置、当前必须继续运行，或仍需独立发送提醒。实际配置状态必须有独立的操作结果依据。

## 2. 最小修订路径

只补九条旧标注不能保护未标注的原文补位；直接让模型总结全部历史会引入新的抽取误差和调用成本。本次实现采用：**先提供人工核实的字段关系，再在选择历史时同时检查相关更新**。

候选层的实验关系为：`reopen_for_review`（重新复核具体字段）、`replace_field`（明确替代字段）、`supplement`（另一个字段的补充）。它们由独立的 `select_revision_context()` 消费，**不是现有 `assemble()` 的新参数**。`reopen_for_review` 不能直接写成永久 `supersedes`，`supplement` 不能冒充撤销。

每条关系需有较早/较新事件、作用字段、精确项目/任务范围，以及较新表达的可核验来源。字段与关系当前由人工提供，不声称自动语义发现。记录整理时间保留真实值，历史重建明确注明事后标注。

1. 先按来源创建/可见时间、请求范围和生效区间确定当时适用的关系；尚不可见或范围不适用的关系不改变当前判断，也不能因它缺少目标而阻断更早的回放。助手建议不升级成用户修订。
2. 对适用关系核对来源及字段：目标缺失、错误地连接不同范围或没有相应证据时明确报错，不生成可送模型的输入。未来才可见的变更不能降低当时旧信息的有效性。
3. 如选择旧消息，相关且可见的后续更新须一起考虑。原文保留，但附带字段状态：当前请求、待复核、历史表达或冲突。不能仅补选新原文而让旧整条消息继续冒充当前偏好。
4. 补位检索也受同一检查。已选事件按 ID 去重、最终按源顺序呈现；排名是审计数据，不是事实优先级。
5. 当前回归保留四条历史上限；预算约束仍必选。若相关证据及必选项超过条数/字节上限，返回 `budget_incomplete` 与遗漏原因，不输出看似完整的模型输入。该策略可能牺牲可用性，属于下一单元需核验的取舍；不能静默截断到只剩旧值。

此阶段不要求完整长期记忆图谱，也不推断所有自然语言都已正确分组。没有覆盖的主题仍是已知限制。

## 3. 待复核不等于必须打断

`needs_recheck` 描述信息状态，不直接决定“用户现在必须回答”。普通项目推进可以保留提醒时间未知，继续独立可做的工作。若下一动作确实依赖精确时刻，应先查已有证据或澄清，不能猜测后执行。下一选择器保留这一边界，不硬编码所有案例都不提问；真正的打扰成本仍需人类反馈。

## 6. 离线接口（2026-10-26）

[检查层](../../tools/experiments/select_revision_context_v0_1.py)提供纯函数：

```python
result = select_revision_context(
    events, relations,
    as_of="2030-01-07T09:00:00Z", project="SyntheticNotebook",
    seed_ids=["E1"], required_ids=["E0"],
    max_history_records=4, max_history_bytes=10000,
)
```

- `events` 使用合成案例的字段：事件 ID、精确范围、来源级别、创建与可见时间、原文及人工 `claims`。可选 `valid_from` / `valid_until`。调用者须先核对来源；本函数不认证 transcript 或自动理解原文。无标注的原文仍可能包含本层未识别的变更。
- 本接口不是旧情境记录的兼容入口：不支持 `recheck_after`，传入该键会抛 `ValueError`，避免将未处理的复核期限静默变成当前表达。调用者须保留原适配器的复核结果并明确投影语义，不能直接复制旧记录或把复核期限等同于失效时间。
- `relations` 必须指向同范围、时间有先后的明确用户事件。重新复核不等于永久撤销；明确替代只影响相同字段。已知重新复核不会因其表达的有效区间到期而恢复旧具体值，须有新的明确表达解决该字段。
- 旧表达的来源已可见但生效日尚未来到时，允许当前修订引用它；旧表达仅随合法关系作为历史证据保留，不提前激活未受影响字段，且计入容量。尚未生效的新修订仍不改变当前判断；已可见、已生效的新端与关系范围不符时明确报错。复核已经被替代的旧值，不会降级其后的当前值。
- `seed_ids` 为调用者的检索候选顺序，`required_ids` 为必须保留的证据（如已确认预算）。关联证据组优先于无关联的补位；同字段同范围的竞争表达一并选择，避免漏掉未显式连边的冲突。同刻不兼容的明确表达即使后来要求重新复核，仍保留冲突，直到新的明确值解决它。组过大时保守返回不完整，不承诺一定能填满输入。
- 呈现顺序按来源创建时间、可见时间、ID 稳定排序；ID 不用于选择同刻冲突的胜出值。重复来源 ID 拒绝，输入对象不被修改。
- 成功返回 `status=ready` 和 `model_input.history`；各消息的 `fields` 含值、`current` / `historical` / `needs_recheck` / `conflict`、证据 ID 和原因。`current` 仅代表有支持的当前表达，不能证明执行成功、配置状态或长期偏好。未受影响的旧流程表达保留原出处，不推断取消或已运行。
- 字段状态在精确范围内计算；任务请求可携带项目与任务两种范围的表达，本层不把它们合成为一个最终配置值，也未定义任务覆盖项目的策略。调用方不得去掉范围后把多个 `current` 当成同一条已解决的指导。
- 来源原文及人工字段值始终是待解释的数据，不是可执行指令。下游须在独立数据区中引用它们，保留来源级别和范围；`ready` 不认证语义真实性，也不保证抵御提示注入或证明实际配置。
- 有效关系错误、必选证据不可用、容量不足及选中冲突分别返回 `invalid_relation`、`required_unavailable`、`budget_incomplete`、`conflict`，`model_input` 均为 null；格式错误抛 `ValueError`。无关联可选补位放不下时带原因省略。
- 字节上限计算完整 `model_input` 的紧凑、键排序 UTF-8 JSON，包含字段标记和请求性质说明；不包含外层模型提示或服务端框架。审计 `excluded` / `omissions` / `errors` 可能提及不可用来源，不得复制进模型事实。
- 本接口不产生 `needs_user_reply_now`，不把待复核强制映射为即时追问。实际回答与教学负担由后续实验判断。

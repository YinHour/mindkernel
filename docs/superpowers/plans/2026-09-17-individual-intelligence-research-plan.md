- 时间预算：主要开发者每周 3–5 小时，首个周期建议为六个周迭代，总计 18–30 小时。

- 依据：[个体智能方向讨论纪要](../../05-history/2026-09-17-individual-intelligence-direction.md)及其后的 RSI 调研、资源约束和协作者侧写讨论。
- 执行说明：这是研究路线，尚未冻结实现架构。采用[推进—review—更新流程](../../06-execution/iteration-log.md)，每次工作形成证据与接续动作。提醒按用户后续要求单独设置，实验不随提醒自动执行。

## 1. 目标与本周期问题

长期目标：通过与特定人类共同工作，培养能够持续理解其意图、接受教导、观察和求证，并发展自身专长的个体智能。不同经历应有机会形成有价值的差异。

本周期只回答一个核心问题：

> 持续更新对协作者的认识，并记录教导的情境和依据，能否在后续新任务中改善场景理解、减少重复纠正，而且额外教学成本可以接受？

六周结束时应交付一组可追溯案例、一份对照结果和下一步投入决定。结果可以是有效、无明显收益或证据不足；新增侧写条目、规则或技能数量均不直接代表成长。

### 1.1 已明确的条件

- 首位协作者是主要开发者，Codex 是拟议的首个共同工作环境。
- 用户后续将 Codex 数据接入提高为第一周优先事项；先建立限定范围的只读数据入口，持续监听和双向集成另行按需要推进。
- 持续侧写涵盖基础信息、当前状态、兴趣和意愿，并服务于场景理解。
- 允许模型较小和知识欠缺；神经网络是候选智慧载体，规模和更新方式尚未选择。
- 对话、提问、工具操作、冲突求证和专长形成都是长期目标的一部分。
- 每周可投入 3–5 小时个人时间；额外算力和服务费用尚未设定。

### 1.2 本计划提出、仍可调整的选择

- 第一周先打通 Codex 可见对话读取，再选择少量协作片段进行回放；具体见[第一周实验计划](2026-09-17-week1-codex-data-experiment-plan.md)。
- 以现成模型加普通记忆检索作为主要对照；把动态侧写作为第一项候选改进。
- 同时只进行一个实验，每两轮做一次继续、缩小或停止的判断。
- 本周期依次探索侧写、纠正、提问与技能迁移；后续轮次以之前的证据为前提。
- 小型参数模块和持续自动采集各自有进入条件，不按周数自动启动；Codex 只读数据入口已提前到第一周。

## 2. 最小学习闭环

共同工作片段 → 保存当时可见的事实 → 更新协作者模型 → 形成当前场景理解 → 选择回答、提问或求证 → 接收反馈 → 修正认识 → 在后续新情境中检验。

### 2.1 协作者动态模型

| 层次 | 内容 | 更新原则 |
| --- | --- | --- |
| 基础背景 | 角色、知识经历、工作环境、资源条件 | 保留来源和最近确认时间，不能永久冻结 |
| 长期倾向 | 兴趣、长期目标、取舍方式、协作习惯 | 从多次证据形成有条件的判断，记录反例 |
| 当前状态 | 任务阶段、可用时间、正在关注的事项，以及本人表达的精力状况 | 明确适用范围、失效条件；过期转为未知或待确认 |
| 当前意愿 | 本次目标、探索或实施意图、当前约束与行动决定 | 优先依据当前明确表达，不能用历史偏好覆盖 |

侧写记录的最小内容：判断内容、所属层次、适用情境、证据引用、证据性质（明确表达／行为观察／推测）、记录时间、有效范围或复核条件、认识状态（已确认／暂定／待求证／已失效）、反例与修订记录。第一轮可用表格表达，不预先建设完整数据库。

情绪或动机无法判断时保留未知；一句简短回复不应直接变成稳定人格标签。兴趣不等于当前意愿，当前意愿也不自动代表具体行动已经获准。

### 2.2 场景理解的最小输出

每个案例在揭示后续反馈之前，记录五项内容：

1. 当前任务目标及硬约束。
2. 与本任务有关的协作者背景、状态和意愿，附证据。
3. 对当前需求的判断，以及仍不确定的地方。
4. 建议下一步，以及是否值得先提问或查证。
5. 实际反馈揭示后的修订及原因；此项不得提前进入模型输入。

示例：已知“每周 3–5 小时”和阶段约束，应形成相应范围的推进建议。用户后续已要求提高 Codex 数据优先级并建立工作流程，因此要更新当前行动意图；更早的“暂不接入”不能作为永久偏好。该变化可用于开发案例，但当前助手已知后续反馈，不能据此进行盲测。

### 2.3 与自身能力成长的关系

协作者模型解释“这个人在此情境下需要什么”；领域经验和技能记录“什么方法有效”；能力记录表达“自己会什么、何时需要帮助”。三者分开记录、共同参与判断。

第一周期的提问实验只检验与当前任务有关的信息获取。开放式好奇心、主动探索新的专长及多个成长轨迹的比较，留到后续单独检验，不能由此次结果推断已经实现。

## 3. 每周工作方式与资源控制

| 活动 | 每周时间 | 产出 |
| --- | --- | --- |
| 挑选并核对共同工作片段 | 30 分钟 | 少量真实案例，保留来源及当时信息边界 |
| 阅读外部方法 | 30 分钟 | 最多两个候选，形成采用或暂缓理由 |
| 一个小实验 | 90–180 分钟 | 一个可与基线比较的变更及结果 |
| 复核与决定 | 30–60 分钟 | 保留、修改、放弃或补充证据 |

合计 180–300 分钟。日常标记案例计入上述时间，不额外要求逐条审阅全部工作记录。若每周只有三小时，优先缩小案例和实现范围。

- 主要开发者负责表达真实意图、纠正关键误解、确认结果是否有用。
- 开发助手可以整理材料、提出实现、运行比较和撰写结果；不能代替人类判定其真实意愿。
- 每轮开始写明时间和调用上限，到上限即记录当前结果，不自动扩大实验。
- 模型预算同时记录调用次数、可得的 token／费用、耗时；已有订阅也记录资源消耗。
- 首轮可以采用已有工具和人工回放，不要求购买 GPU、模型服务或新订阅。若后续确需额外付费，应先列出具体金额与预期能消除的不确定性，再决定是否投入。
- 同时最多一个正在执行的实验；准备队列最多两个候选。

## 4. 六轮推进安排

### 第 1 轮：优先建立 Codex 数据入口、案例与比较方法

**问题：哪些片段能够客观地检验协作者理解？**

- [x] 先按第一周计划实现并验证限定任务的数据读取、上下文过滤、来源定位、结构化回复及去重；W1-01 已通过 review，助手原始时间缺失保留为已知限制，后续再准备学习案例。
- [x] 起步选择 6 个真实输入片段，涵盖预算、阶段与意愿变化、文稿纠正等，来自 2 个任务组；另列 1 个合成日期边界案例，不把它计入真实效果。
- [x] 每个片段标明判断时点，后来的反馈单独保存；同一任务的近似片段归组。当前输入 C06 尚无后续效果反馈。
- [ ] 按时间和事件组划分开发与留出案例；写下分组、评分规则和每次实验资源上限。
- [x] 用现成模型加普通记忆检索完成最小基线；历史限于截止点之前，另保存 2 次 review 后的补充情境回放，不冒充留出评价。
- [ ] 对每个案例记录判断、依据、人工纠正和成本，建立首份实验记录。

**交付：** 小型案例集、评估协议、基线记录。真实样本不足时，合成边界案例可检验机制，但要单独标注，不计作真实协作效果。

当前限制：分组、评分与调用预算已有记录，但独立留出案例、协作者逐例判断和完整人工成本尚缺，因此相关项继续保留未完成。初始基线与补充回放只支持 W1-03 的工程假设：明确约束和当前任务状态需要可靠进入输入。

**完成条件：** 案例的输入与后续反馈分离；评分规则能说明什么算误解；至少跑通一个完整比较过程。不能把历史回放当成已经完成前瞻性长期观察。

### 第 2 轮：验证动态侧写与场景理解

**问题：动态侧写能否比普通记忆更好地处理情境和意愿变化？**

- [ ] 以第 2 节的最小表格生成侧写候选，逐条保留证据性质和适用条件。
- [ ] 只改变侧写组织与更新方式，保持基座模型、可用历史、工具和实验总预算可比。
- [ ] 在开发案例中检查旧状态失效、临时条件、当前意愿覆盖历史判断等情况。
- [ ] 方法冻结后打开尚未查看的留出案例，记录得失并做逐例复核。
- [ ] 标记错误来自证据缺失、检索失败、侧写更新还是后续推理；不把所有失败归结为模型太小。

**交付：** 第一份侧写快照、场景判断对照、失败分类。

**第一个检查点：** 能观察到有依据的改善，或在相同表现下减少成本，才扩大实验。若结果相同，保留较简单方案；若出现不可靠标签，先修正证据与更新规则。

### 第 3 轮：验证纠正与冲突更新

**问题：一次教导能否改变后续行为，同时保留其适用边界？**

- [ ] 选择一类重复发生的误解，把教导的原因、情境与例外补全。
- [ ] 在一条时间序列上依次呈现旧认识、新反馈和新的任务，比较更新前后的判断。
- [ ] 分别检查“明确改变意愿”“旧记录缺少条件”“世界事实存在冲突”，避免使用同一种覆盖规则。
- [ ] 对事实冲突记录待核实项及可观察证据；当前意愿以本人的明确表达为依据。
- [ ] 复查旧案例，确认新教导没有使原本正确的行为退步。

**交付：** 可追溯的认识修订记录、迁移案例、回归结果。

**完成条件：** 能指出一次更新如何影响后续新情境；若没有改善，保留反例并缩小规则范围，不能只报告“已写入记忆”。

### 第 4 轮：验证有效提问与教学负担

**问题：主动获取缺失信息，能否减少误解而不过多打扰协作者？**

- [ ] 从已经出现的失败中选择需要澄清的案例，同时加入信息已经足够的案例。
- [ ] 比较现有方案与增加提问选择的方案；允许提问的两个比较组使用一致的交互上限。
- [ ] 第一轮提问实验暂设每任务最多一次澄清，作为控制成本的实验条件，非永久产品限制。
- [ ] 提问前记录预期消除什么不确定性；回答后检查判断是否发生有用变化。
- [ ] 记录提问次数、回答和额外解释时间、后续纠正与返工；沉默按未收到反馈处理。

**交付：** 有效与无效提问案例、教学成本记录。

**第二个检查点：** 若任务改善主要依赖大量新增人工指导，或提问经常无助于判断，下一轮先改善问题选择。证据不足时继续观察，不因到达第四周就宣称形成主动学习能力。

### 第 5 轮：从经验形成一项可迁移技能

**问题：共同工作经验能否改善一类具体任务的完成能力？**

- [ ] 从案例中选择一类确实重复出现的任务，由经历决定方向，例如资料证据核对或代码问题定位。
- [ ] 形成一份最小技能说明：适用条件、操作方法、失败信号和不适用情境。
- [ ] 与使用相同历史材料的普通记忆方案比较，至少包含新的同类问题和一个不适用的反例。
- [ ] 分开记录个体独立处理、调用工具和向通用大模型求助的结果；获得外部答案不能直接记为独立掌握。
- [ ] 核对任务产物或可观察结果。缺少客观验证时，保留人工判断及证据局限。

**交付：** 一项候选技能、适用边界和迁移结果。此时最多证明局部技能形成，不宣称已经发展稳定专长。

### 第 6 轮：验证外部方法与决定下一周期

**问题：哪项改进值得保留，下一笔投入应花在哪里？**

- [ ] 选择前几轮记录的一个主要瓶颈，以及一个与之对应的外部机制；没有合适候选时用于复核已有结果。
- [ ] 在相同资料和预算下比较引入前后效果，不同时替换模型、记忆和评估方法。
- [ ] 使用尚未用于调整的新案例；同一模型版本下重跑对照，排除基座或提示变化造成的假进步。
- [ ] 汇总六轮的案例、改进、退步、人工时间和模型消耗。
- [ ] 作出下一周期决定：保留并观察、修正一个瓶颈、开展小型参数实验、研究最小接入，或暂停当前路径。

**交付：** 六轮复盘、一份保留方案和下一周期唯一优先问题。

## 5. 评估和继续投入条件

### 5.1 比较方式

- 主对照：同一基座模型加普通记忆检索；候选方案使用相同的原始历史和当前输入。
- 辅助对照：无个人历史，用于了解历史信息的贡献，不能只靠战胜这个较弱条件证明复杂方案必要。
- 若添加外部教师或更多推理轮次，必须记账；必要时增加同预算对照，区分机制收益和资源增加。
- 记录模型标识、运行日期、提示版本、采样设置、历史截止点和案例版本。无法固定服务端版本时，明确限制并同期重跑对照。
- 侧写生成、检索、反思、额外澄清等都计入成本，不能只计算最终回答。
- 普通记忆已能正确处理的案例应保留，防止新增模块只优化某个难例却破坏整体协作。

### 5.2 避免把记住答案当成学习

- 开发案例可反复查看；留出案例只在方法冻结后使用。
- 未来反馈不得进入历史快照、侧写、技能或提示。历史回放只能支持有限的机制判断。
- 留出案例一旦用于修改方法，就转为回归案例；以后以新案例评估迁移。
- 同一事件的改写不能分别充当教学样本和独立检验样本。
- 后续自然发生的新任务，先保存判断，再接收反馈，作为前瞻性证据。
- 在可行时隐去方案名称后做人工比较。模型评分只能辅助筛查，不能独自判定人的真实意图。

### 5.3 观察指标

| 维度 | 记录内容 |
| --- | --- |
| 场景理解 | 目标、当前意愿与约束是否理解正确；列出逐例结果 |
| 侧写可靠性 | 无证据推断、过期状态误用、临时条件固化的次数及来源 |
| 修正与迁移 | 教导后新情境中的改善；旧能力的退步 |
| 提问价值 | 是否消除关键未知；不必要提问与未解决问题 |
| 协作成本 | 额外教学分钟、重复解释、返工时间、等待时间 |
| 资源成本 | 调用、token、可得费用及实验维护时间 |

样本较小时报告“具体哪些案例改善或退步”，不把百分比变化解释为稳定总体效果。机制边界案例的通过是最低要求，不能替代真实协作收益。

### 5.4 决策规则

- **保留：** 新案例出现可说明原因的收益，成本可接受，未引入未解释的关键退步；继续积累前瞻性证据。
- **简化：** 候选与基线效果接近时，优先保留维护更少、成本更低的方案。
- **修正：** 错误集中在一个清楚的机制缺陷，下一轮只针对该缺陷修改。
- **补证据：** 案例不足或判断不一致时，不增加架构复杂度，先补充案例或澄清评分依据。
- **暂停当前路径：** 连续两轮都无法识别收益且维护或教学负担上升，停止扩展该机制，保留材料和失败结论。两轮是资源控制建议，不是项目整体失败判据。

## 6. 吸收业界经验的方法

采用漏斗：发现 → 与当前失败匹配 → 阅读原始材料 → 提取一个机制 → 小实验 → 保留或暂缓。

每个外部候选只记录：来源及版本日期、改变了什么、作者如何验证、与自身问题的关系、最小尝试成本、采用或暂缓理由。实现复用前再检查版本、许可证与依赖；当前不引入新依赖。

| 参照 | 可借鉴的机制 | 本周期定位 |
| --- | --- | --- |
| [PAHF](https://arxiv.org/abs/2602.16173) | 行动前澄清与行动后纠正结合 | 对照第 3–4 轮；其模拟用户实验不能替代真实协作观察 |

## 9. 后续投入的进入条件

### 9.1 小型神经网络或个人适配层

当普通记忆方案在同一类问题上持续失败，已有可核对的教学案例及独立检验案例，而且维护与算力预算可承受时，再考虑参数实验。

第一个模块只承担一种能力，如经验适用性判断或提问选择；与简单规则和同预算的现成模型比较。需要检查新情境迁移、遗忘、是否依赖外部教师以及真实成本。若样本不足，继续积累，不能用六周期限推动训练。

### 9.2 Codex 数据读取与后续自动接入

用户已把数据入口列为高优先级：第一周先读取一个明确任务的可见对话，建立来源、时间与质量约定。不要把整个 Codex 集成平台当作取得首批数据的前提。

当人工刷新成为主要负担时，再研究 Hooks 或其他最小增量入口；需要把实验结果回传到工作过程时，另行设计工具接口。当前没有安装插件、启用 Hooks 或启动后台监听。单纯读取或接入成功不能作为成长验收。

### 9.3 专长、多样性和长期成长

至少需要跨时间的新任务结果，才能讨论稳定专长；需要多个独立成长轨迹，才能讨论不同经历是否产生有价值的多样性。第一个六周周期的单人小样本不能证明这些长期主张，也不能证明已经实现 RSI。

## 10. 第一轮的具体起点

W1-01 数据读取和 W1-02 案例／回放已通过工程 review。下一次从推进记录的 W1-03 接续：先花 15–30 分钟确定最小情境字段、来源与时效规则，围绕检索遗漏和当前任务状态做边界检查。开发案例不能转作独立验证；每次结束前更新证据与下一步。

第一条候选研究问题：**把“当前处于方案探索、每周 3–5 小时”表达为有适用范围的认识，能否帮助系统提出合适的下一步，并在后来明确改变意愿时及时修正？**

这条案例是起点，不能独自承担整个评估。首轮还需补充其他独立事件，才能判断该机制是否具有可迁移价值。
